# Voltra device model

**When to read this.** You're getting oriented to what a Voltra actually is, what its modes mean, what the four layers of "load" vocabulary refer to, or you hit a units gotcha (especially the eccentric one).

The skill assumes a working mental model of the hardware. The single most important fact is in the next section. Read that even if you skip the rest.

## What a Voltra is

A Voltra is an **electromagnetic resistance unit**. There are no physical plates, no stack, no chains. The resistance is generated by a motor that the device drives in real time according to the active training mode and its settings.

Consequences:

- **Setter values are virtual.** `device.set_weight {lbs: 30}` doesn't move a pin; it writes a setting the device uses to compute resistance. The change is effectively instant when accepted, but see "under tension" below.
- **`device.set_chains` is a virtual chain curve**, not a physical attachment. It scales resistance with cable position. The device caps chains at the current weight; `chainSettingLbs` in `get_state` shows the value it kept. Which end of the rep is heavier is an open question; do not tell the user.
- **`device.set_eccentric {overloadLbs}` is pounds, not percent.** The parameter used to be called `percent`, which was a misnomer; `percent` still works as a deprecated alias with identical pound semantics. `{overloadLbs: 8}` at 30 lb concentric is about 38 lb on the eccentric. Negative values assist the eccentric. For "+25% eccentric" at 30 lb, pass `8`.
- **A positive eccentric overload raises the pull on the wall mount.** The true peak is concentric plus overload. With no mount rating configured, the result carries `mountLoadWarning`; read it out. With a rating configured (`VMCP_MOUNT_RATING_LBS`), a peak above it is refused before the write (VW-274). Overload is a cost knob, not a growth multiplier: `coaching.explain {topic: "live.eccentric_overload_cost"}`.
- **A weight change written while the cable is under tension does not apply to the set in progress.** The device holds the engaged load until the cable goes slack. The write still goes through, and the setter now says so in `weightChangeWarning` (null otherwise). `weight_implied_mismatch` catches it after the fact. Change weight between sets.

## The four layers (glossary, VW-156)

"Load" is used for four different things across the tool surface. Keep them apart (canonical write-up: voltras-mcp `docs/vocabulary.md`):

| Layer                   | What it means                                                                                                               | Tools                                                                                                                                                | Where you read it                                                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Settings**            | The numbers the device will use: weight, eccentric overload, chains, damper level, band max force, isokinetic speeds        | `device.set_weight`, `set_eccentric`, `set_chains`, `set_damper_level`, `set_band_max_force`, `configure_isokinetic`, `bilateral.cascade`            | `get_state.weightLbs`, `chainSettingLbs`, `damperLevel`; `settings_update` events                                                                                                     |
| **Mode**                | Which training program the device runs: WeightTraining, ResistanceBand, Damper, Isokinetic, Isometric, Rowing, CustomCurves | `device.set_mode`, the `mode` field of `bilateral.cascade`, `device.enter_row_mode`                                                                  | `get_state.requested_mode` (what was asked for) and `active_mode` (what the device reports)                                                                                           |
| **Engagement**          | Whether the motor is physically pulling on the cable right now                                                              | `device.start_guided_load` (a ceremony for starting from a contracted position), `device.unload` (release), `set.start` (engages from a slack cable) | `get_state.load_state` is `loaded` only for guided load and rowing. It reads `unloaded` during ordinary weight-training reps, so it is not a "is the cable hot" check for normal sets |
| **Recording lifecycle** | What the MCP is persisting: a session, the set inside it, the reps inside that                                              | `session.start` / `set_exercise` / `end`, `set.start` / `end`                                                                                        | `get_state.active_set`; `set_started` / `set_ended` events; `session.get`                                                                                                             |

Rules that fall out of the table:

- Settings persist across mode switches on the device. Flip to Isokinetic and back and your weight, chains and eccentric are still there.
- Mode first, then settings. `bilateral.cascade` does both in one call for WeightTraining, and waits for the device to echo a changed mode before it writes the rest. For Isokinetic and every other non-WeightTraining mode, set the mode alone first (see `02-setter-cascade-and-verification.md`).
- `set.start` is a recording action that also engages the motor from slack. It does not run the guided-load ceremony, and from a pre-extended cable it will not engage at all (VMCP-02.22).
- When the user says "load 40 pounds," that is a **setting** (`set_weight`), not guided load. When they say "start me from the bottom position," that is guided load.

## After a connect: acceptance and the first state report

- The device must **accept** a connection. A first pairing asks the lifter on the device, so `device.connect` can take up to 30 s. `get_state.connectionState: "awaitingAcceptance"` means it is waiting. A refusal or no answer is `CONNECTION_REFUSED`, never retried for you.
- Until the device has reported its settings on this connection, `get_state.state_confirmed` is false and setters refuse with `DEVICE_STATE_UNKNOWN`. Wait a moment and re-read. Stops and unloads are never held back.

## Training modes

Use the name string in tool calls.

| Name             | What it does                                              | Notes                                                                                                                                                                                          |
| ---------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WeightTraining` | Constant load, modulated by eccentric overload and chains | The default for almost all strength work and the safe state to land in                                                                                                                         |
| `ResistanceBand` | Position-dependent force curve, mimics elastic resistance | `set_band_max_force` 15..70 lb                                                                                                                                                                 |
| `Rowing`         | Concentric-only, velocity-tracked                         | Two-stage entry: `device.enter_row_mode` then `device.start_row {distance?}`. `set.start` refuses in Rowing with `ROWING_USE_TWO_STAGE`                                                        |
| `Damper`         | Resistance proportional to velocity                       | Used by `slot.identify` because the screen changes legibly. Guided load cannot be entered from Damper                                                                                          |
| `CustomCurves`   | User-defined force curves                                 | Not used by this skill                                                                                                                                                                         |
| `Isokinetic`     | Speed-capped; load adjusts to hold a target velocity      | `device.configure_isokinetic` in one call. Enter it with `device.set_mode` per slot, not through a cascade (VW-162, open)                                                                      |
| `Isometric`      | Hold against a fixed point                                | `isometric.measure_hold`, `measure_max`, `measure_imbalance`. Caller sets mode and a low weight first. It can pull up to 400 lb per unit whatever weight is set; see the mount warning in `04` |

`Idle` exists but is not selectable. A device that wakes in Idle suppresses telemetry; `start_guided_load` handles this with a preflight, `set.start` does not, so set a mode first.

## Settings, per setter

| Setter                                                                                                                          | Unit and range                                                           | Notes                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `device.set_weight {lbs}`                                                                                                       | 5..200 lb integer                                                        | The headline number. Set it before `set.start`; the set header snapshots it there                                                                                                                                                                                  |
| `device.set_eccentric {overloadLbs}`                                                                                            | -195..+195 lb                                                            | Pounds on the eccentric. `percent` is a deprecated alias, same meaning                                                                                                                                                                                             |
| `device.set_chains {lbs}`                                                                                                       | 0..100 lb                                                                | Device caps at weight                                                                                                                                                                                                                                              |
| `device.set_assist_mode {mode}`                                                                                                 | `on` / `off`                                                             | Lives in the device's Settings menu                                                                                                                                                                                                                                |
| `device.set_damper_level {level}`                                                                                               | 0..9 (screen shows 1..10)                                                | Damper mode only                                                                                                                                                                                                                                                   |
| `device.set_band_max_force {lbs}`                                                                                               | 15..70 lb                                                                | ResistanceBand only                                                                                                                                                                                                                                                |
| `device.configure_isokinetic {targetSpeedMmPerSec, eccMode, eccConstWeightLbs?, eccOverloadWeightLbs?, eccSpeedLimitMmPerSec?}` | speeds 0..2000 mm/s in steps of 10 (screen shows m/s); weights 0..200 lb | Replaces the five `set_isokinetic_*` setters, which are deprecated. Setting either eccentric weight makes the device beep; the write still succeeds. Per-unit isokinetic settings differ if the units have different histories and this tool cannot read them back |

Mode-config setters (damper, assist, band, isokinetic) get no confirmation echo from the device, so a coercion check on them expires silently. Verify with `get_state` and, for isokinetic, with the user reading the screen.

## Slot vocabulary

The server tracks up to two slots, logical bindings to physical devices:

- **`primary`**: single-device sessions when no side binding is used.
- **`left`** / **`right`**: bilateral sessions, or a single device connected with `slot: 'auto'` against a persisted binding. A bilateral rig has no `primary` slot at all.

Every channel event carries `meta.slot`. `slot.bind` and `slot.bindings_list` persist the device-to-side map; `slot.swap` flips a reversed mapping in memory without touching the device.

## Sessions vs sets vs reps

```
session (one per slot per "I'm starting a workout"; carries the current exercise pointer and the lifter label)
  └─ set (one per bout; copies the session's exerciseId and lifter when it starts; carries a setPurpose)
       └─ rep (one per eccentric-to-concentric boundary, with per-phase velocity, ROM, force)
```

A session is **per slot**. A bilateral workout has two sessions, one on `left` and one on `right`, unless you only record on one. A session holds several exercises over time via `session.set_exercise`; the pointer when the set starts is what the set keeps. `set.end` persists the reps and recalculates the exercise baseline for that exercise and side.

A **training day** is a distinct local calendar day with an ended session. Twelve sessions on one day are one training day. Every attendance figure counts training days.

**Auto-arm (default on).** With a session open and no set armed, the server opens a set itself on the lifter's own reps and publishes `set_started {auto_armed: true}`. It waits for a second rep so a positioning pull is not rep 1. `server.health.autoArm` reports it. An **idle rep** is a rep pulled with no session open, or one the arm did not adopt; idle reps are batched into `idle_rep_summary` every 5 s and never persisted.

## What the device cannot do

- **No vision, no form check.** It sees velocity, ROM and force, not joint angles or bar path.
- **No HRV, music, or video.**
- **No mode change mid-set.** A mode revert during a set latches an abort that blocks the next `set.start` (`SET_ABORTED_BY_MODE_REVERT`).
- **No user profile on the device.** Settings are device-wide. Two people sharing a cable see the same last values.
- **No lifter accounts in the MCP.** A set carries a free-text `lifter` label (absent means the owner). A guest has no profile, tier or baselines. See the second-lifter recipe in `04-set-execution.md`.
- **Guided load needs the lifter.** It sits in `armed` until someone extends and holds the cable; a timeout means nobody did, not that the device wedged. See `02-setter-cascade-and-verification.md`.
